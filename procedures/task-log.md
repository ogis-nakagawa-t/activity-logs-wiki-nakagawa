# タスクの記録

- 記録の時刻（HH:MM）は、記録のたびに `scripts/now.ps1` を実行して取得する。ユーザーが時刻を指定した場合はそれを優先する。
- 対象は、業務開始時に作った今日の `10_Daily/YYYY/MM/DD.md`（構成は `.foam/templates/daily-note.md` に従う）。日付をまたいでも同じファイルに記録する（AGENTS.md の「日々のタスク」）。
- タスクの開始・中断・終了の時刻は `## 📝 作業ログ` にだけ書く。`## ✅ タスク` には時刻も所要時間も書かない。
- 記録行の形式: `- [種別] @[カテゴリ/プロジェクト名] タスク名 — 内容`（種別: 内容 / メモ / 調査。時刻は付けない）
- 作業ログ行の形式:
  - 開始時: `- HH:MM ～ [進行中] @[カテゴリ/プロジェクト名] タスク名`
  - 完了・中断時: 同じ行を `- HH:MM ～ HH:MM [種別] @[カテゴリ/プロジェクト名] タスク名 — 所要 X.XXh。成果` に更新する（種別: 完了 / 中断。終了時刻は [完了] / [中断] の時刻。成果が無ければ `— 所要 X.XXh` だけ）

## カテゴリ/プロジェクトの指定

- `@[カテゴリ/プロジェクト名]` は「カテゴリまたはプロジェクト」の名前を表し、`@[名前]`（例: `@[休み]`）で指定する。`@[開発/クラウドデータ基盤]` のように `/` で区切って、カテゴリの下にプロジェクトを書いてもよい。
- ユーザーが「<タスク>を開始 @[…]」のように指定したらそのまま記録する。省略時は同タスクの既存の指定を引き継ぎ、無ければ `@[未分類]` とする。ただし、`profile.md` に既定の `@[カテゴリ/プロジェクト名]` が書かれているときは、そちらを優先する（AGENTS.md の「個人の好みは profile.md と CLAUDE.local.md を優先する」に従う）。

## dailyの構成との対応

- 「計画」= `## ✅ タスク` の `### やること`（`- [ ]` / `- [x]`）。繰り越しは `### 繰り越し`、持ち越しは `### 次回への持ち越し` に書く。
- 記録行（内容 / メモ / 調査）は、対応する「やること」項目の直下にインデント付きの子項目として追記する。[開始] / [完了] / [中断] の子項目は書かず、状態は「やること」のチェック（`[x]` / `[ ]`）で表す。
- `## 📝 作業ログ` には、[開始] のたびに [進行中] の作業ログ行を1行追記し（時刻順）、[完了] / [中断] のときにその行を更新する。1区間を1行で表す。
- 特定のタスクに紐づかない `[メモ]` は、`## 📝 週報に記載しないメモ` に追記する。週報に載せたい内容は、タスクの子項目として書く。
- 問題・アイデア・学んだことは、それぞれ `## 🚨 問題`・`## 💡 アイデア`・`## 🖊️ 学んだこと` に、1件ごとに `### タイトル` を立てて書く。
- 工数は `## ⏱ 工数` の表（`@[カテゴリ/プロジェクト名]` / プロジェクトコード / タスク / 工数(h) / 備考）に記入し、末尾の「合計」行を更新する。単位は時間(h)、0.25刻み。
- プロジェクトコードは `project-codes.md` から引く。照合と未登録時の扱いは procedures/project-codes.md の「参照」に従う。PJコード別・カテゴリ別の集計は日次ノートには書かず、週報の作成時に工数表から行う。
- テンプレートにない `##` 見出しは追加しない。`###` / `####` 見出しを足すのは、問題・アイデア・学んだことの各項目だけとする。

## 種別ごとの処理

- **開始**: 「やること」に該当する項目が無ければ `- [ ] タスク名` を追加する（子項目は書かない）。`## 📝 作業ログ` に [進行中] の作業ログ行を追記する。
- **内容**: `[内容]` に発言をそのまま記録する。200字超、または手順・ログ・コマンド出力を含む場合は 40_Notes/ に切り出し、dailyから `[[40_Notes/…]]` でリンクする。
- **完了**: 直近の同タスクの [進行中] の作業ログ行を [完了] に更新し、終了時刻と所要時間（その行の開始時刻から計算）を書く。成果が分かれば1行添える。「やること」のチェックを `[x]` にする。あわせて所要時間を0.25h単位に丸めて「⏱ 工数」表に記入する（同タスクの行が既にあれば加算、無ければプロジェクトコードを引いて1行追加）。ユーザーが工数を指定したらそれを優先する。作業ログ行の所要時間と表の値は一致させる。
- **メモ**: `[メモ]` を追記（置き場所は上記のとおり）。
- **調査**: 40_Notes/YYYY-MM-DD_<slug>.md を作り、dailyの該当タスクの子項目に `[調査]` 行とリンク（`[[40_Notes/…]]`）を書く。
- 40_Notes/ にノートを作る・切り出すときは（tech-research スキルで調査レポートを作るときも）、AGENTS.md の「図」に従い、図にできる箇所があれば図（SVG を基本とし、Mermaid も可）を入れ、すぐ下に `> [図の説明]` を付ける。
- **中断**: 直近の同タスクの [進行中] の作業ログ行を [中断] に更新し、終了時刻と所要時間を書く。「やること」のチェックは `[ ]` のままにする。中断までの所要時間を「⏱ 工数」表に加算する（行の追加とプロジェクトコードは完了時と同じ。再開後の分は [完了] 時にさらに加算される）。再開予定が翌日以降なら `### 次回への持ち越し` にも追加する。再開したら [開始] として新しい [進行中] の作業ログ行を追記し、次の [完了] / [中断] までを別の1行にする。
- **問題**: `## 🚨 問題` の末尾に、次のひな形の `{...}` を埋めて追記する（複数件あれば時系列で下に足す）。発言は `#### 詳細` に書く。発言に原因・対応・結果が含まれていれば該当する `####` に書く。内容の無い `####`（原因候補など）は、続報で埋めるため空のまま残す。続報（「原因: …」「対応: …」「結果: …」など）は、直近の同じ問題の該当する `####` に追記する。各 `####` の中身は箇条書き（`- `）にせず、文章で自由に書く。関連タスクがあれば文中で `@[カテゴリ/プロジェクト名] タスク名` に触れる。タイトルはユーザーが指定しなければ、発言から短く付ける。

  ```markdown
  ### {問題のタイトル}

  #### 詳細

  {発言の内容}

  #### 原因候補

  #### 対応策

  #### 結果
  ```

- **アイデア**: `## 💡 アイデア` の末尾に、次のひな形の `{...}` を埋めて追記する（複数件あれば時系列で下に足す）。発言は箇条書き（`- `）にせず、文章で自由に書く。タイトルの付け方は問題と同じ。

  ```markdown
  ### {アイデアのタイトル}

  {発言の内容}
  ```

- **学んだこと**: `## 🖊️ 学んだこと` の末尾に、次のひな形の `{...}` を埋めて追記する（複数件あれば時系列で下に足す）。発言は `- HH:MM 内容` で書く。タイトルの付け方は問題と同じ。手順・ログ・コマンド出力を含む長い内容は、[内容] と同じ基準で 40_Notes/ に切り出してリンクする。

  ```markdown
  ### {学んだことのタイトル}

  - {HH:MM} {発言の内容}
  ```

## 共通ルール

- タスク名のない「完了」は、作業ログの直近の [進行中] 行のタスクとみなす。複数あって判断できないときだけ確認する。
- 開始時刻の訂正（例: 「開始時刻は9:00だった」）は、作業ログ行の開始時刻を直し、所要時間と工数表も合わせて直す。
- 既に書かれている記録（「やること」の下の時刻付きの子項目など、以前の形式の行）は削除も書き換えもしない。[進行中] の作業ログ行が無く、以前の形式の `HH:MM [開始]` 子項目があるときは、その時刻を開始時刻として使う。
- 書き込み前に機密情報の有無を確認し、あればマスクする。
- 報告は、記録の内容を1行（例: 記録しました: 10_Daily/2026/04/16.md）。使用した MCP サーバー・Agent Skill の1行は、この行数に含めず別に添える（AGENTS.md の「記録ルール」）。プロジェクトコードが未登録だったときは、記録の行に「未登録: @[…]」を添える。
