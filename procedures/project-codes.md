# プロジェクトコード対応表の参照と追加

対応表はルートの `project-codes.md` にある。

## 参照（工数表にコードを書くとき）

- `@[…]` から照合キーを決める。`/` を含まなければ中身全体（例: `@[休み]` → `休み`）、含むときは最後の `/` より後ろ（例: `@[開発/クラウドデータ基盤]` → `クラウドデータ基盤`）をキーにする。キーと表の1列目を完全一致で照合する。
- 一致した行の PJコードを、「⏱ 工数」表のプロジェクトコード列に書く。PJコード別の集計では、その行のプロジェクト名称も使う。
- 一致しなければ空欄のままにし、推測でコードを書かない。`@[未分類]` は常に空欄にする。
- 未登録のときは、報告の1行に「未登録: @[…]（『プロジェクトコードを追加』で登録できます）」と添える。

## 追加（「プロジェクトコードを追加: …」）

1. 受け付ける形式:
   - Excel からコピーしたタブ区切りの6列（費用区分 / PJコード / 目的コード / 顧客名(敬称略) / プロジェクト略称 / プロジェクト名称）。複数行でもよい。
   - 「@[キー] PJコード …」のような項目の指定。
2. キーの指定が無ければ、プロジェクト略称の【】内の語をキーにする（例: `【休み】有休、特休な` → `休み`）。【】が無ければキーを尋ねる。キーが `/` を含めて指定されたら（例: `@[開発/クラウドデータ基盤]`）、最後の `/` より後ろ（`クラウドデータ基盤`）をキーにする。
3. 値は貼り付けられたまま写す（`ー` などの記号も変えない）。分からない列は空欄にする。空行は無視する。
4. 既存のキーと重複するときは上書きせず、確認する。PJコードが既存の行と同じときは、別のキーとして追加してよいか確認する。
5. 表の末尾に行を追加する。
6. 報告は1行（例: `追加しました: project-codes.md（@[休み] → A295482100）`）。

変更・削除を頼まれたときは、該当する行を編集する（行の削除はファイルの削除に当たらない）。

## プロジェクトコード利用の基本方針

- TECH:工数および費用
  - 技術開発に関わる労務費（工数）、経費（購買費、旅費交通費など）
    - Databricks、Snowflakeの検証や打合せのための交通費などこちらを使用
  - 他部署支援の費用振替する労務費（工数） ※なお、それを費用振替する際のプロジェクトは COM
    - 顧客案件の作業工数、打合せ交通費などこちらを使用
  - 技術開発以外の社内業務に関わる労務費（工数）

- COM:工数の費用振替用、経費など費用
  - 他部署支援の費用振替する経費（旅費交通費など）
    - BAC打合せ ⇒共通プロジェクトで運用する
  - 技術開発以外の社内業務に関わる経費（旅費交通費など）
    - 名刺作成 ⇒共通プロジェクトで申請する
    - 社有Wi-Fi、モバチョ ⇒共通プロジェクトで申請する
    - クラウドサービス利用の請求 ⇒長期にわたる場合は共通プロジェクトで登録する。開発テーマ期間内の利用であればテーマ側PJTコードで登録する

**余談**:

- 8H系は過去、オフィス宅ファイル系で使われていた組織コードらしい。8H配下の古いプロジェクトコードを使用しないように気を付けたほうが良い
- 共通PJT、BP按分用定型プロジェクトは自動で作成されるらしい。
