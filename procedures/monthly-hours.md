# 月末処理の工数入力データを作成する

Excel の工数入力ブックに貼り付けるデータを、対象月の日次ノート（`10_Daily/YYYY/MM/DD.md`）の「⏱ 工数」表から作る。集計とファイルの書き込みは `scripts/month-hours.ps1` が行う。手で数えたり、書き写したりしない。

## 出力

| ファイル                  | 内容                                                                                                                                                                                              |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `70_工数入力/YYYY/MM.tsv` | Excel に貼り付けるデータ。1行が1つのプロジェクトID、列は1日〜末日（月により28〜31列）のタブ区切り。ヘッダ行・プロジェクトID・名称・目的コード・月間計の列は無い。工数の無い日は空欄。             |
| `70_工数入力/YYYY/MM.md`  | 確認用の完全版。Excel と同じ列（代表PJ / 割合(%) / プロジェクトID / 空 / プロジェクト名称 / 目的コード / 空 / 月間計 / 1日〜末日）の表、曜日の行、合計行、リスト外のIDと未登録の `@[…]` の注記。 |

- 行の順番は、profile.md の `## 月末処理の工数入力で入力するプロジェクトIDの順番` に従う。当月の工数が 0 の ID も、空欄だけの行として出す（Excel の行とずれないように）。
- 順番のリストに無い ID に工数があれば、TSV には入れない。MM.md の注記と報告に、ID と日別の工数を書く。
- プロジェクトコードが空欄の行は `project-codes.md` で補う（procedures/project-codes.md の「参照」と同じ照合）。補えない `@[…]`（`@[未分類]` を含む）は、どの ID にも入れず、MM.md の注記と報告に書く。
- 目的コードは、プロジェクトID `A295482100`（【休み】有休、特休など）だけ `HLD`、ほかは空欄。MM.md にだけ出る。
- MM.md のプロジェクト名称は、順番のリストで ID の後ろに書いたメモを使う。メモが無ければ、`project-codes.md` で先に出る行のプロジェクト名称を使う。
- MM.md には frontmatter と図を付けない。

## profile.md の節の書き方

profile.md は利用者が書く（エージェントは参照のみ）。節が無い、空、ID が重複している場合、スクリプトはエラーで止まる。そのときは作成を止め、次の例を示して利用者に書いてもらう。

```markdown
## 月末処理の工数入力で入力するプロジェクトIDの順番

1. A295481100 【庶務】事務、打合せ
2. A295482100 【休み】有休、特休など
3. A313271100 【技術開発】クラウドデータ分析基盤
```

- 番号付きリスト（`1.`）でも箇条書き（`-`）でもよい。各行の先頭にプロジェクトID、その後ろにメモ（MM.md のプロジェクト名称になる）を書く。
- 順番は Excel の工数入力シートの行の順番にそろえる。

## 手順

1. 対象月を決める。「月末処理の工数入力データを作成して（2026年10月）」のように指定があればそれを使う。指定が無ければ、`scripts/now.ps1` の日付を参考に、対象の年月をたずねる（1回だけ）。
2. 集計結果を確かめる。

   ```powershell
   ./scripts/month-hours.ps1 -Year 2026 -Month 10 -Format report
   ```

   - エラーで止まったら、上の「profile.md の節の書き方」を示して終える。
   - 出力の `[totals]` は ID 別の月間合計、`[not_in_order_list]` はリスト外の ID、`[unregistered]` は未登録の `@[…]`、`[invalid_hours]` は工数が数値でない行。`daily_notes` は対象月の日次ノートの件数。
   - `[invalid_hours]` があれば、該当する日次ノートの工数を直すか利用者に確認する（推測で直さない）。直したら 2 からやり直す。
3. ファイルを書く。`-Write` を付けると、スクリプトが `70_工数入力/YYYY/MM.tsv` と `MM.md` を書き（ディレクトリが無ければ作り、既存のファイルは上書きする）、書いたパスと 2 と同じ集計結果を出力する。

   ```powershell
   ./scripts/month-hours.ps1 -Year 2026 -Month 10 -Write
   ```

   - この2つのファイルは Write ツールで書かない。ツールの出力では行末のタブや空欄だけの行が消えるため、TSV を正しく写せない。スクリプトは UTF-8（BOMなし）・LF を指定して書くので、文字コードは崩れない（AGENTS.md「実行環境」の例外）。
   - 中身を直したいときも、ファイルを手で編集せず、日次ノートや profile.md を直してから 3 をやり直す。

4. 書いたファイルを確かめる。BOM が無い、CR が無い、TSV の行数が順番のリストの ID の数、各行の列数がその月の日数、の4つがすべて `True` ならよい。

   ```powershell
   $y = 2026; $m = 10
   $path = '70_工数入力/{0}/{1:D2}.tsv' -f $y, $m
   $bytes = [IO.File]::ReadAllBytes((Resolve-Path -LiteralPath $path))
   $lines = [Text.Encoding]::UTF8.GetString($bytes).TrimEnd("`n").Split("`n")
   -not ($bytes.Length -ge 3 -and $bytes[0] -eq 0xEF -and $bytes[1] -eq 0xBB -and $bytes[2] -eq 0xBF)
   @($bytes | Where-Object { $_ -eq 13 }).Count -eq 0
   $lines.Count -eq @(./scripts/month-hours.ps1 -Year $y -Month $m).Count
   @($lines | Where-Object { $_.Split("`t").Count -ne [DateTime]::DaysInMonth($y, $m) }).Count -eq 0
   ```

5. 報告する。
   - 書いたファイル（TSV と MD）を1行で。
   - ID 別の月間合計。
   - リスト外の ID、未登録の `@[…]` があれば、その内容（Excel に入らないので、profile.md への追記や `プロジェクトコードを追加` を促す）。
   - 貼り付け方: 「`MM.tsv` を VS Code で開いて全選択・コピーし、Excel の工数入力シートで、1行目のプロジェクトの『1日』のセルを選んで貼り付ける」。Excel で TSV を直接開くと、BOM が無いため文字化けすることがある。
6. コミットは、利用者に頼まれたときか、業務終了（procedures/day-end.md）のときに行う。
