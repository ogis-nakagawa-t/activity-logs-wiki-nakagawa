# Query（問い合わせ）

この手順は、SKILL.md の共通規則（構成・メタデータ・根拠の不変条件・図・規約）を先に読んでから従う。

wiki を検索して質問に答える。トリガーの例:

- 「<X> について何を知っている？」
- 「<Y> に関することをまとめて」
- 「wiki をもとに A と B を比べて」

## 手順

1. `90_Wiki/index.md` を読んで候補の記事を探す。続けて、テーマの主要な語句*とその同義語*で 90_Wiki/ を全文検索する。索引と全文検索の両方で何も見つからないうちは、「wiki に関連する内容はない」と言ってはいけない。そう答えるときは、検索したことも伝える。
2. 見つけた記事を読み、答えをまとめる。
3. 自分の学習知識より wiki の内容を優先する。引用元は、ルート相対パスの Markdown リンクで示す（例: `[記事タイトル](90_Wiki/topic/slug.md)`）。
4. 答えは会話の中で返す。頼まれない限り、ファイルは書かない。

## アーカイブ

ユーザーが答えを wiki に保存するようはっきり頼んだとき:

1. 答えを新しい wiki ページとして書く。形式は `archive-template.md`（このファイルと同じディレクトリ）を見ること。
   - frontmatter に `sources` は書かない。答えの中で引用した wiki 記事は、本文の wikilink と「関連項目」で示す。
   - 会話中の Markdown リンクは、ページ内では wikilink（`[[90_Wiki/topic/slug]]`）に書き換える。
   - ファイル名は問いのテーマを表すものにする（例: `transformer-architectures-overview.md`）。
   - いちばん近いトピックのディレクトリに置く。
   - 記事と同じく、図にできる箇所を探し、あれば SKILL.md の「図（diagram-design）」に従って入れる。
2. 必ず新しいページとして作る。既存の記事には統合しない。アーカイブの中身はまとめた答えであって、元資料ではないからだ。
3. `90_Wiki/index.md` を更新する。要約の先頭に `[アーカイブ]` を付ける。
4. SKILL.md の「ログの月ごとのまとめ」を行ってから、`90_Wiki/log.md` に追記する。
   ```
   ## [YYYY-MM-DD] query | アーカイブ: <ページタイトル>
   ```
