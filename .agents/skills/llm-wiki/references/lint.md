# Lint（点検）

この手順は、SKILL.md の共通規則（構成・メタデータ・根拠の不変条件・図・規約）を先に読んでから従う。

wiki の品質を点検する。点検は3つに分かれ、それぞれ手を入れてよい範囲が違う。

## 安全な修正（自動で直す）

次のものは自動で直す。

**索引の整合**: `90_Wiki/index.md` と、実際の 90_Wiki/ の `.md` ファイル（index.md・log.md・月ごとのログ `90_Wiki/YYYY/MM.md` を除く）を比べる。図の SVG は索引に載せない。

- ファイルがあるのに索引にない → `(要約なし)` の仮の要約で行を足す。更新日は記事の frontmatter の `updated`（アーカイブなら `archived`）を使う。なければファイルの最終更新日を使う。
- 索引の行が存在しないファイルを指している → 索引で `[MISSING]` と印を付ける。行は消さず、判断はユーザーに任せる。
- 索引の更新日が記事の `updated`（アーカイブなら `archived`）と違う → 索引の行を記事に合わせる。

**内部リンク**: 90_Wiki/ の記事の本文にあるすべての wikilink と Markdown リンク（図の画像リンク `![...](...)` を含む）を確かめる。ただし、「関連項目」の節のリンク（下の規則で扱う）、`#` で始まるページ内リンク（目次のアンカー。下の「目次」で扱う）、index.md・log.md（上で扱った）・月ごとのログは除く。

- リンク先が存在しない → 同じファイル名のファイルを 90_Wiki/ の別の場所で探す。
  - ちょうど1つ見つかった → パスを直す。
  - 見つからない、または複数ある → ユーザーに報告する。

**根拠ファイルの参照**: `sources` にあるすべてのパスが、存在するファイルを指していなければならない。

- 指す先が存在しない → 同じファイル名のファイルを、許可された情報源ディレクトリ（80_Raw/・10_Daily/・40_Notes/）の別の場所で探す。
  - ちょうど1つ見つかった → パスを直す。
  - 見つからない、または複数ある → ユーザーに報告する。

**Foam のキー**: 90_Wiki/ の記事とアーカイブページ（index.md・log.md・月ごとのログを除く）の `title` と `tags` を確かめる。80_Raw/ は編集しないので、見つけても報告だけにする。

- `title` がない、または本文の H1 と違う → H1 に合わせる。
- `tags` がない、または固定タグ（`wiki` など）かトピック名が欠けている・順序が違う → SKILL.md の「メタデータ（frontmatter）」の規則どおりに直す。内容タグは消さない。

**目次**: 90_Wiki/ の記事とアーカイブページ（index.md・log.md・月ごとのログを除く）の `## 目次` を確かめる。直しても `updated` は変えない（書式だけの修正）。

- 目次がない → H1 の直後に、H2 見出しから作って足す。
- 目次が H2 見出し（「目次」自身を除く）と、項目・順序・アンカーのどれかで食い違う → 目次を H2 見出しに合わせて直す。

**関連項目**: トピックのディレクトリごとに確かめる。

- 関連項目のリンク先が存在しない → 同じファイル名のファイルを 90_Wiki/ の別の場所で探す。
  - ちょうど1つ見つかった → パスを直す。
  - 見つからない → リンクを外す（切れた相互リンクは何の根拠にもならない）。
  - 複数ある → ユーザーに報告する。

## 機械的なレポート（直さない）

次のコマンドで機械的に調べる。

```powershell
python .agents/skills/llm-wiki/scripts/check_evidence.py .
```

後ろに記事のルート相対パスを並べると、範囲を絞れる。既定の範囲は wiki 全体で、スクリプトは速い。見つかったことは報告し、事実を自動で直してはいけない。

**資料への忠実さ**: 報告される「疑い」は候補であって、結論ではない。自分で計算した値や製品名も出てくる。それぞれを元資料の文脈と照らし合わせ、本当に食い違うものだけを報告する。

**根拠エラー**: スクリプトが確かめられない記事。`sources` がない、パスが解決できない、許可された情報源ディレクトリの外を指している、のいずれか。スクリプトでは直せないので、必ず判断が要る。

図の `<title>`・`<desc>`・`<text>` にある数値・日付も、記事の `sources` と照合され、見つからないものは「（図 <ファイル>）」付きで疑いに出る。

**図の点検**: 図のファイルがない、直後に `> [図の説明]` がない、SVG に `<title>` か `<desc>` がない（または空）、どの記事からも参照されていない SVG がある、のいずれか。図を描き直すか、`> [図の説明]` を足すかは判断が要るので、報告だけにする。参照されていない SVG は、要らないものなら `99_Archive/` へ移すことを提案する。

**参照されていない raw ファイル**: ログ（log.md と月ごとのログ）で「新規知見なし」とした raw ファイルは除かれる。残りは、まだ記事にしていない資料の一覧として扱う。

## 判断が必要なレポート（直さない）

次のものは自分の判断で見つける。見つけたことは報告し、自動では直さない。

- 記事同士の事実の食い違い
- 新しい資料で置き換わったのに、状態ブロックなしで書かれたままの古い主張
- 資料の見解が分かれているのに、注記がない箇所
- 関連する記事同士なのに、明らかに相互リンクが足りない箇所（提案だけする。黙って足さない）
- 形式が崩れた状態ブロック（「更新済み」に日付がない、どちらかのブロックに説明がない。形式は `article-template.md`（このファイルと同じディレクトリ）を参照）
- 他の wiki 記事から1つもリンクされていない孤立ページ
- 足りないトピック間の相互リンク
- よく出てくるのに、専用のページがない概念
- 引用元の記事がアーカイブ後に大きく更新されたアーカイブページ
- SVG の文字（`<text>`）や Mermaid のコードと `> [図の説明]` の食い違い、または本文から外れた図（図にあって説明にない文字、本文が更新されたのに古いままの図）
